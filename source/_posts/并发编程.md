## 进程与线程

### 一 进程

1. 当一个程序被运行，从磁盘加载到这个程序的代码至内存，这是就开启了一个进程。
2. 进程就是一个程序的实例

### 二 线程

1. 一个进程内分为多个线程
2. 一个线程就是一个指令流，将指令流中的一条条指令以一定的顺序交给CPU
3. 线程作为最小调度的单位，进程作为资源分配的最小单位，在windows中进程是不活动的，只是作为线程的容器

### 三 两者对比

进程基本上相互独立，而线程存在于进程内，是进程的子集
进程拥有共享的资源，如内存空间，供其内部的线程共享
进程间通信复杂
线程通信相对简单，因为他们共享进程内的内存
线程更加轻量，线程上下文切换成本一般上要比进程上下文切换低

##  并行与并发

### 一 并发 （Concurrent）

同一时间应对（dealing with）多件事情的能力。

单核CPU下，线程实际还是串行执行。操作系统中有个组件叫任务调度器，将CPU的时间片（windows时间片最小约15ms）分给不同的线程使用，只是由于CPU在线程间的切换非常快，给人类的感觉是同时运行的。这种线程轮流使用的CPU的做法叫做并发

### 二 并行 （Parallel）

同一时间做(doing)多件事情的能力

多核CPU下，每个 核 都可以调度运行的线程，这时候线程是并行的。


### 三 应用

#### 1 异步调用

需要等待结果返回，才能继续运行的就是同步
不需要等待结果返回，就能继续运行就是异步

同步在多线程中还有另外一层意思，是让多个线程步调一致

比如在项目中，视频文件需要转换格式等操作，，比较费时，这时候开一个新的线程处理视频转换避免阻塞主线程

#### 2 提升效率

充分利用多核cpu的优势，提高运行效率。想象下面的场景，执行3个计算，最后将计算结果汇总

计算1 花费 10ms
计算2 花费 11ms
计算3 花费 9ms
汇总需要1ms

串行执行 需要 10 + 11 + 9 + 1 = 31ms
并行执行的花费时间去觉得最长的那个线程的运行时间 即11ms 再加上汇总时间，为12ms

#### 3 结论

单核CPU下，多线程不能实际提高程序运行效率，只是为了能够再不同的任务之间切换，不同线程轮流使用cpu，不至于一个线程总占用一个cpu

多核cpu可以并行跑多个线程，但能否提高程序运行效率还是要分情况


IO操作不占用CPU,只是我们一般拷贝文件使用的是阻塞IO，这时相当于线程虽然不用CPU，但需要一直等待IO结束，没能充分利用线程。因此后面才有 非阻塞IO 和 异步IO 优化

### 三 原理之线程运行
#### 1 栈与栈帧

每个栈由多个帧组成，对应每次方法调用时所占用的内存
每个线程只能有一个活动帧，对应着当前正在执行的那个方法


#### 2 线程上下文切换

从使用cpu到不使用cpu 就是一次上下文切换
当任务调度器分给每个线程运行的CPU时间片用完之后，分给其他线程，这就叫线程上下文切换

以下原因导致CPU不再执行当前的线程，转而执行另一个线程代码

1. 线程cpu时间片用完
2. 垃圾回收
3. 有更高优先级的线程需要运行
4. 线程自己调用了sleep, yield, wait，join, park, synchronized, lock 等方法 

当Context Switch发生时，需要由操作系统保存当前线程的状态，并恢复另一个线程的状态，Java中对应的概念就是程序计数器，他的作用就是记住下一条jvm指令的执行地址，是线程私有的

状态包括程序计数器，虚拟机栈中 每个栈帧的信息，如局部变量，操作数栈，返回地址等
Context Switch频繁发生会影响性能

#### 3 方法详解

一 start与run

为什么需要调用start 而不是直接用run ？
答： 因为如果直接调用run 代表着会在当前线程去处理重写run的方法，而start才会在开启的新线程里用

使用start前，线程是 NEW状态 使用start后，线程变成 RUNNABLE状态

二 sleep与yield

sleep
1) 调用sleep会让当前线程从Running进入TimeWaiting （有时限的等待状态）
2) 其他线程可以使用interrupt方法打断正在睡眠的线程，这是sleep方法会抛出InterruptedException
3) 睡眠结束后的线程未必会立刻得到执行
4) 建议用TimeUnit 的 sleep 代替 Thread的sleep来多的更好的可读性 TimeUnit.SECONDS.sleep(1) 睡1s

yield

1) 调用yield会让当前线程从RUNNING进入RUNNABLE 就绪状态，然后调度执行其他线程，相当于是让出了CPU的使用权
2) 具体的实现依赖于操作系统的任务调度器

RUNNABLE和TIMED WAITING 状态最大的区别就是 CPU时间片还可能会分给RUNNABLE状态的线程，并且sleep方法是有等待时间的

3 线程优先级

线程优先级会提示调度器优先调度该线程，但它仅仅是一个提示，可以忽略他
如果cpu比较忙，那么优先级高的线程会获得更多的时间片

4 sleep实现

在没有利用cpu来计算时，不要让while(true) 空转 浪费cpu，这时可以使用yield或者sleep来让出cpu的使用权给其他程序

可以用wait 或者 条件变量达到类似的效果
不同的是，后两种都要加锁，并且需要相应的唤醒操作
sleep适用于无需锁同步的场景

5 join
代表着等待某个线程运行结束

6 interrupt

阻塞

线程打断标记初始状态默认为假 false

打断sleep的线程，会清空打断状态，sleep wait join ，isinterrupted为false

打断正常运行的线程，不会清空打断状态，即 isinterrupted为true

如果用stop退出去，

8 守护线程

默认i情况下，Java进程需要等待所有线程都运行结束才结束。有一种特殊的线程叫做守护线程，只要其他的非守护线程都运行结束了，即使守护线程的代码没有执行完，也会强制结束

垃圾回收器线程就是一种守护线程
Tomcat中的Acceptor 和 Poller线程都是守护线程，所以Tomcat接收到shutdown命令后，不会等待它们处理完当前请求

#### 4  五种状态

从操作系统方面描述的

初始状态  仅是在语言层面创建了线程对象，还未与操作系统线程相关联
可运行状态（就绪状态）   可以被os的调度程序被调度，但是暂时没有得到cpu的时间片
运行状态    获得cpu时间片运行中的状态 运行和可运行可以来回切换
阻塞状态    
- 如果调用了阻塞API，如BIO 读写文件，这是该线程实际不会用到CPU，会导致线程上下文切换，进入阻塞状态
- 等BIO操作完毕，会由操作系统唤醒阻塞的线程，转换至可运行状态
- 与可运行状态的区别是，对阻塞状态的线程来说只要他们一直不换形，调度器就一直不会考虑调度他们
终止状态 表示线程已经执行完毕，生命周期已经结束，不会再转换为其他状态

##  共享模型之管理线程

一段代码块内如果存在对共享资源的多线程读写操作，称这段代码块为临界区

### 1 synchronized

synchronized 是阻塞式方案，俗称 对象锁，它采用互斥的方式让同一时刻之多只有一个线程能持有对象锁，其他线程在想获取这个对象锁时就会阻塞住。这样就能保证拥有锁的线程可以安全的执行临界区的代码，不用担心线程上下文的切换

``` java

import lombok.extern.slf4j.Slf4j;  
  
@Slf4j(topic = "test17")  
public class Test17 {  
  
  
public static void main(String[] args) throws InterruptedException {  
Room room = new Room();  
Thread t1 = new Thread(() -> {  
for (int i = 0; i < 1000; i++) {  
room.increment();  
}  
});  
Thread t2 = new Thread(room::decrement);  
  
t1.start();  
t2.start();  
t1.join();  
t2.join();  
  
log.debug("{}", room.getCounter());  
}  
}  
  
class Room {  
private int counter = 0;  
  
public void increment() {  
synchronized (this) {  
counter++;  
}  
}  
  
public void decrement() {  
synchronized (this) {  
counter--;  
}  
}  
  
public int getCounter() {  
synchronized (this) {  
return counter;  
}  
}  
}

```

### 2 线程安全分析

成员变量和静态变量是否安全？

如果没有被共享 则线程安全
如果被共享，分两种情况
1 如果只有读操作 则安全
2 有读有写的话，则这段代码时临界区，则不安全

局部变量是不是线程安全？

**是的**

但局部变量引用的对象未必安全
- 如果该对象没有逃离方法的作用范围，则是线程安全的
- 如果该对象逃离方法的作用范围，则是不是线程安全的

#### 暴露引用

如果有子类继承了父类的 public方法 并重写了，会出现 暴露引用的问题

#### 常见线程安全类
String Integer StringBuffer Random Vector Hashtable java.util.concurrent包下的类
他们每个方法都是原子的，但是他们多个方法的组合并不是原子的！

Integer等都是不可变类，因为期内不得状态不可以改变，因此它们的方法都是线程安全的，比如String类里的 substring replace 等方法，但是他们是new String 新建个对象，原来的值不变

外星方法：比如一个类有一个抽象方法，但这个抽象方法可以被继承的类实现。 因此这种可能是不安全的

开闭原则 ：即开放封闭原则，是指软件实体(类，模块，方法等) 应当是可扩展的，不是可修改的。在不修改已有代码的前提下，扩展新的功能（比如String类，就是定义为final，防止自己的方法被继承的类修改）
在Java中，可以通过以下方式来遵守开闭原则：
1. 抽象化：为系统的可变部分制定好接口，而不去实现它们。
2. 封装变化：将可能变化的部分封装起来。
3. 多用组合少用继承：可以使用组合来替代类的继承，以获得更大的灵活性。
4. 使用依赖注入：依赖注入可以使得在运行时动态地将依赖关系注入到对象中。

Api介绍

object.wait() 让进入object 监视器的线程到waitSet等待
obj.notify() 在 obj 上 正在waitSet等待的线程中挑一个唤醒
obj.notifyAll() 在 obj 上 正在waitSet等待的线程中全部唤醒

#### 一 wait notify正确使用

sleep(long n) 和 wait(long n) 的区别
1. sleep是Thread的方法， wait是 Object的方法
2. sleep不需要和synchronized一起用， 但wait需要
3. sleep在睡眠同时 不会释放锁，但wait会
4. 他们的线程状态都是一样 TIMED_WAITING

用 锁对象的话 在前面加上final，保证引用不会被修改

```
synchronized(lock) {
	while(false){
		lock.wait();
	}
}

synchronized(lock) {
	lock.notifyAll();
}
```

### ReentrantLock

相对于 synchronized 来说  具备一下特点
- 可中断
- 可以设置超时时间
- 可以设置为公平锁（防止饥饿）
- 支持多个条件变量（多个waitset，即不满足条件一的去一个waitset 不满足条件二的去另一个waitset）

#### 一 可重入
可重入是指同一个线程如果首次获得了这把锁，那么因为他是这把锁的拥有者，因此有权利再次获取这把锁。如果是不可重入锁的话，第二次获取锁的时候，自己就也会被挡住

和synchronized一样，都支持可重入区别在于：
sychronized是会自动释放，但是reentrantLock需要手动释放

``` java

import lombok.extern.slf4j.Slf4j;  
  
import java.util.concurrent.locks.ReentrantLock;  
  
@Slf4j  
public class Test22 {  
  
private static ReentrantLock lock = new ReentrantLock();  
public static void main(String[] args) {  
lock.lock();  
try {  
log.info("1");  
m1();  
} finally {  
lock.unlock();  
}  
}  
  
public static void m1() {  
lock.lock();  
try {  
log.info("emter m1");  
m2();  
} finally {  
lock.unlock();  
}  
}  
  
public static void m2() {  
lock.lock();  
try {  
log.info("emter m2");  
  
} finally {  
lock.unlock();  
}  
}  
}
```

#### double-checked locking

饿汉式：类加载时就会导致该单例对象被创建

懒汉式：类加载时不会导致该单例对象被创建，而是首次使用该对象时才会创建

``` java
public final class SingleTon {

}

}  
}  
}
```

以上代码的特点
1 懒惰实例化
2 首次使用sychronized才会加锁 后续不需要加锁
3 但是第一个Instance 是在同步代码块之外 有可能会发生代码重排


问题在于Java的内存模型（Java Memory Model, JMM）和指令重排序（Instruction Reorder）。当执行`INSTANCE = new SingleTon();`时，这个操作在JVM中可能被分解为以下三个步骤（在概念上）：

1. **分配内存**给`SingleTon`的实例（INSTANCE）。
    
2. **初始化`SingleTon`的构造器**。
    
3. 将`INSTANCE`引用指向分配的内存。
    

在Java中，步骤2和步骤3之间的顺序可能会被编译器和运行时优化，这意味着在没有适当同步的情况下，一个线程可能在步骤3之后但步骤2之前看到`INSTANCE`引用。如果此时另一个线程检查`INSTANCE`（非null），它可能会错误地认为`INSTANCE`已经完全初始化了，并尝试使用它，尽管实际上它的构造器可能还没有运行完毕。

也就是说 可能回将调用构造器的顺序和将分配内存的顺序反过来

### 自定义线程池

多线程环境的编程中，我们经常遇到让多个线程等待在一个条件上，等到这个条件成立的时候我们再去唤醒这些线程，让它们接着往下执行代码的场景。假如某一时刻条件成立，所有的线程都被唤醒了，然后去竞争锁，因为同一时刻只会有一个线程能拿到锁，其他的线程都会阻塞到锁上无法往下执行，等到成功争抢到锁的线程消费完条件，释放了锁，后面的线程继续运行，拿到锁时这个条件很可能已经不满足了，这个时候线程应该继续在这个条件上阻塞下去，而不应该继续执行，如果继续执行了，就说发生了虚假唤醒。

**`awaitNanos`的返回值**：`awaitNanos`方法在被唤醒或等待超时时会返回一个`long`值，表示剩余的等待时间（以纳秒为单位）。如果返回值为0或负数，则表示等待时间已经耗尽或已经超时。这个返回值在循环中被用来更新`nanos`变量，从而确保如果线程被唤醒但条件未满足，它会继续等待剩余的时间（如果有的话）

特点：核心线程数 == 最大线程数 ，即没有救急线程被创建，也因此不需要超时时间
阻塞队列是无界的LinkedBlockingQueue， 是一个基于链表实现的阻塞队列，默认情况下，该阻塞队列的大小为Integer.MAX_VALUE，由于这个数值特别大，所以 LinkedBlockingQueue 也被称作无界队列，代表它几乎没有界限，队列可以随着元素的添加而动态增长，但是如果没有剩余内存，则队列将抛出OOM错误。所以为了避免队列过大造成机器负载或者内存爆满的情况出现，我们在使用的时候建议手动传一个队列的大小。

 符号  >>> 代表 无符号向右移动

比如输入10，10-1=9，9化成二进制就是：1001。
然后开始这步：

n |= n >>> 1;
1
此时n=1001,n先右移1位，变成0100。
然后0100再与之前的n做或运算，也就是0100|1001=1101。
此时n=1101。

然后是：

n |= n >>> 2;
1
1101>>>2=0011
0011|1101=1111
此时n=1111。

然后是：

 n |= n >>> 4;
1
聪明的人已经知道了，以后的结果都是1111，不信给你算。
1111>>>4=0000
0000|1111=1111
此时n=1111。

然后是

 n |= n >>> 8;
1
1111>>>8=0000 0000
0000 0000|1111也就是0000 0000|0000 1111 = 0000 1111
0000 1111也就是1111。
此时n=1111。

移16就不用算了，你得多笨。

这时候发现了啊，一直右移，做或运算，最后就变成了全是1的。然后再看tableSizeFor的代码最后一行，最后要得到n+1。

return (n < 0) ? 1 : (n >= MAXIMUM_CAPACITY) ? MAXIMUM_CAPACITY : n + 1;
1
这段代码先是判断n是否小于0，这个防御判断就不用管了。大于0的时候，判断n和MAXIMUM_CAPACITY的大小，取值MAXIMUM_CAPACITY或者n+1。

这里可以这么理解：
n >= MAXIMUM_CAPACITY 可以写成n + 1 > MAXIMUM_CAPACITY
也就是：
(n + 1 > MAXIMUM_CAPACITY) ? MAXIMUM_CAPACITY : n + 1;
然后就理解成，n+1和MAXIMUM_CAPACITY谁大就取谁。

我们输入的10，最后得出1111，1111+1之后是几？是10000，16，也就是2的4次方。
