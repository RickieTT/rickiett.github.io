### 两阶段终止模式

修改之前 用if 判断中断退出的逻辑

``` java
import lombok.extern.slf4j.Slf4j;  
  
@Slf4j  
public class Test3 {  
  
public static void main(String[] args) throws InterruptedException {  
TwoPhaseTermination twoPhaseTermination = new TwoPhaseTermination();  
twoPhaseTermination.start();  
  
  
Thread.sleep(4000);  
log.info("stop monitoring");  
twoPhaseTermination.stop();  
}  
}  
  
@Slf4j  
class TwoPhaseTermination {  
private Thread monitor;  
  
// 一定得是volatile 因为调用start 和 stop 可能是两个线程+--  
private volatile boolean stop = false;  
  
public void start() {  
monitor = new Thread(() -> {  
while (true) {  
Thread thread = Thread.currentThread();  
if (stop) {  
log.debug("后续处理");  
break;  
}  
try {  
Thread.sleep(1000);  
log.debug("监控ing");  
} catch (InterruptedException e) {  
// throw new RuntimeException(e);  
// e.printStackTrace();  
// thread.interrupt(); // 不再需要重置了 因为这里之前的重置是为了原来if中的判断条件  
}  
}  
});  
monitor.start();  
}  
  
public void stop() {  
stop = true;  
monitor.interrupt();  
}  
}
```


### 同步模式之犹豫模式（Balking）

犹豫模式用在 一个线程发现另一个线程或者本线程已经做了某件相同的事，那么本线程就无需再做，比如下面的监控线程，只需要创建一个线程对象就可以。

``` java

private volatile boolean starting= false;  
  
public void start() {  
synchronized (this){  
if (starting) return;  
starting = true;  
}  
// 真正的启动监控线程
}
```

也经常用在单例模式

## JMM（Java 并发模型）

主要理解共享变量 在多线程间的 **可见性**问题与多条指令执行时的 **有序性**问题

原子性 保证指令不会受到线程上下文切换的影响
可见性 保证指令不会受cpu缓存影响
有序性 保证指令不会受cpu指令并行优化的影响

### 可见性
解决可见性：volatile 但是不能保证原子性
`synchronized` 关键字确保了在进入同步块或方法之前，所有相关的变量都会被刷新到主内存中，并且在退出同步块或方法时，所有对这些变量的修改都会被写回到主内存中。这样，任何进入同步区域的线程都将看到最新的变量值，从而实现了可见性。

### 有序性

JVM在不影响正确性的前提下，可以调整语句的执行顺序

``` java
static int i;
static int j;
i = 1;
j = 1;
```

由于先执行i 还是 j 对结果不影响 。所以在执行这些语句的时候 顺序可以发生变化

**可以加 volatile 防止指令重排序**
比如在j上加 这样就可以防止 j之前的语句发生重排序，因此加一个就行

## 原理

### final原理

![[final原理-图1.png]]


final static int A = 10; final 是会将 -128~127之间的数直接推送到操作数栈中 BIPUSH指令的参数是一个字节，其值范围在-128到127之间。当JVM执行到BIPUSH指令时，它会将该指令的参数值直接推送到操作数栈的顶部。
final static int B = Short.MAX_VALUE + 1; 存放在常量池中 在JVM的指令集中，LDC命令属于ldc系列命令的一部分，该系列命令负责把数值常量或String常量值从常量池中推送至栈顶。这意味着，当Java代码中的某些部分需要使用到常量值时，这些值在编译时被放入常量池中，然后在运行时通过LDC命令来获取和使用。这种机制有助于优化性能，减少内存占用，并提高代码的可维护性。
