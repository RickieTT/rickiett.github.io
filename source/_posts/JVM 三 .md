## 垃圾回收机制

内存泄漏指的是 ：不再使用的对象在系统中未被回收。内存泄露的积累可能会导致内存溢出

java中为了简化对象的释放，引入了自动的垃圾回收机制。通过垃圾回收器来对不再使用的对象完成自动的回收，垃圾回收器主要负责对堆上的内存进行回收。

应用场景：
1 解决系统僵死的问题（可能与频繁的垃圾回收有关）
2 性能优化（对垃圾回收器进行合理的设置可以有效地提升程序的执行性能）

#### 方法区的回收

线程不共享的部分，都是伴随着线程的创建而创建，线程的销毁而销毁。而方法的栈帧在执行完方法之后就会自动弹出栈并且释放掉对应的内存
判断一个类可以被卸载 需要同时满足下面三个条件
1 此类所有的的实例对象都已经被回收，在堆中不存在任何该类的实例对象一集子类对象
2 加载该类的类加载器已经被回收
3 该类对应的java.lang.Class 对象没有在任何地方被使用

如果需要手动触发垃圾回收，可以调用System.gc()方法
调用System.gc()方法不一定会立即回收垃圾，仅仅是向Java虚拟机发送一个垃圾回收的请求，具体是否需要执行垃圾回收，Java虚拟机会自行判断。

-XX:TraceClassLoading -XX:TraceClassUnloading 打印出类的加载和卸载

在OSGi,JSP等热部署场景中，每个jsp文件对应一个唯一的类加载器，当一个jsp文件修改了，就直接卸载这个jsp类加载器。重新创建类加载器，重新加载jsp文件

##### 引用计数法和可达性分析法

如何判断堆上的对象可以回收？
答：Java中的对象是否能被回收，是根据对象是否被引用来决定的。如果对象被引用了，说明该对象在使用，不允许被回收。**（此说法不严谨）**

常见的有两种判断 堆上的对象是否被引用 的方法：
###### 一 引用计数法

缺点：
1 每次引用和取消引用都需要维护计数器，对性能会有一定的影响
2 存在循环引用问题，所谓循环引用就是当A引用B，B同时引用A时会出现对象无法回收的问题
``` java
A a1 = new A();
B b1 = new B();
a1.b = b1;
b1.a = a1;
a1 = null;
b1 = null;
```

由上面代码可以看出 断掉栈内存里 a1 b1 对于堆内存对应的实例对象的引用，但由于 a b 还在循环引用，因此会导致内存泄露

如果需要查看垃圾回收的信息，可以使用 -verbose:gc参数
语法 ： -verbose:gc
###### 二 可达性分析法
Java 使用的时可达性分析算法来判断对象是否可以被回收。可达性分析将对象分为两类：垃圾回收的跟对象(GC Root) 和普通对象，对象与对象之间存在引用关系
[[可达性分析算法示意图]]

A到B再到C和D，形成了一个引用链，可达性分析算法指的是如果从某个对象到GC Root是可达的，该对象就不会被回收

GC Root对象有如下几种类型：
1 线程Thread对象，引用线程栈帧中的方法参数，局部变量等
2 系统类加载器加载的java.lang.Class对象，引用类中的静态变量
3 监视器对象，用来保存同步锁synchronized 关键字持有的对象
4 本地方法调用时使用的全局对象

##### 五种对象引用

可达性算法中描述的对象引用，一般指的时强引用，即时GC Root对象堆普通对象有引用关系，只要这层关系存在，普通对象既不会被回收，除了强引用之外，java中还设计了几种其他引用方式

1 软引用
2 弱引用
3 虚引用
4 终结器引用

###### 一 软引用

软引用相较于强引用是一种比较弱的引用关系，如果一个对象只有一个软引用关联到它，当程序内存不足时，就会将软引用中的数据进行回收

软引用执行过程中如下：
1 将对象使用软引用包装起来，new SoftReference<对象类型>(对象)
2 内存不足时，虚拟机尝试进行垃圾回收
3 如果垃圾回收仍不能解决内存不足的问题，回收软引用中的对象
4 如果依然内存不足，抛出OutOfMemory

软引用中的对象如果在内存不足时回收， SoftReference对象本身也需要被回收，那如何知道哪些SoftReference对象需要回收呢？
SoftReference提供了一套队列机制
1 软引用创建时，通过构造器传入引用队列 
2 在软引用中包含的对象被回收时，该软引用对象会被放入引用队列中
3 通过代码遍历引用队列，将SoftReference的强引用删除

软引用也可以使用继承自SoftReference类的方式来实现

###### 二 弱引用

弱引用的机制和软引用基本一致，区别在于弱引用包含的对象在垃圾回收时，不管内存够不够都会直接被回收, **弱引用主要在ThreadLocal中使用**

``` java
public static void main(String[] args) {  
byte[] bytes = new byte[1024 * 1024 * 100];  
WeakReference<byte[]> weakReference = new WeakReference<>(bytes);  
bytes = null; // 解除强引用  
System.out.println(weakReference.get());  
  
System.gc();  
System.out.println(weakReference.get());  
}
```

###### 三 虚引用

1 在常规开发中不会使用

2 也叫做幽灵引用/幻影引用，不能通过虚引用对象获取到包含的对象。虚引用唯一的用途时当对象被垃圾回收器回收时可以接收到对应的通知。Java中使用PhantomReference实现了虚引用，直接内存中为了及时知道直接内存对象不再使用，从而回收内存，使用了虚引用来实现
###### 四 终结器引用

1 在常规开发中不会使用


##### 垃圾回收算法

###### 核心思想
1 找到内存中存活的对象
2 释放不再存活对象的内存，使得程序能再次利用这部分空间

算法分类
1 标记-清除算法
2 复制算法
3 标记-整理算法
4 分代GC

Java垃圾回收过程会通过单独的GC线程来完成，但是不管使用哪一种算法，都会有部分阶段需要停止所有的用户线程。这个过程被称为STW(Stop the world), 如果STW时间过长则会影响用户使用

GC算法是否优秀可以从三个方面考虑
1 吞吐量
指的是CPU用于执行用户代码的时间与CPU总执行时间的比值，即吞吐量 = 执行用户代码时间 / （执行用户代码时间 + GC 时间）。吞吐量数值越高，垃圾回收的效率越高。

2 最大暂停时间
最大暂停时间指的是所有再垃圾回收过程中的STW时间的最大值。最大暂停时间越短，用户使用系统时受到的影响就越短

3 堆使用效率
不同的垃圾回收算法，对堆内存使用的方式是不同的。比如标记清除算法，可以使用完整的堆内存。而复制算法会将堆内存一分为二，每次只能使用一半内存。因此从堆使用效率来说，标记清除算法要优于复制算法。

一般这三种不可兼得。堆内存越大，最大暂停时间就越长，要想减少最大暂停时间，就会降低吞吐量

<font color="#ff0000">最大暂停时间和吞吐量的关系</font>

1. **相互竞争**：<font color="#ff0000">高吞吐量和低最大暂停时间往往是一对相互竞争的目标。为了实现高吞吐量，GC线程可能会减少执行频率，但每次执行时需要更长的时间来完成内存回收，从而导致较长的暂停时间。相反，为了降低最大暂停时间，GC线程需要更频繁地执行，但这会增加GC的总开销并降低吞吐量。</font>
2. **折衷选择**：在设计或使用GC算法时，必须根据应用程序的具体需求来确定是优先追求高吞吐量还是低最大暂停时间。有些算法（如G1 GC）试图在两者之间找到一个平衡点，以同时满足对吞吐量和暂停时间的需求。
3. **配置调整**：通过JVM的启动参数（如-XX:MaxGCPauseMillis和-XX:GCTimeRatio），可以对GC的行为进行配置，以在一定程度上调整吞吐量和最大暂停时间之间的平衡。然而，这些配置通常需要根据具体的应用程序和硬件环境进行调优。

###### 标记清除算法

一 过程
1 标记阶段，将所有存活的对象进行标记。Java中使用可达性分析算法，从GC Root开始通过引用链遍历出所有存活对象
2 清楚阶段，在内存中删除没有被标记的对象，也就是非存活对象。

二 优点
实现简单，只需要在标记阶段给每个对象维护标志位，第二阶段删除对象即可

三 缺点
1 碎片化问题，由于内存是连续的，所以在对象被删除之后，内存中会出现很多细小的可用内存单元。如果我们需要的是一个比较大的空间，很有可能这些内存单元的大小过小无法进行分配
2 分配速度慢。由于内存碎片的存在，需要维护一个空闲链表，极有可能发生每次需要遍历到链表最后才能获得合适的内存空间

###### 复制算法

一 过程
1 分为两块空间：From 和 To， 每次在对象分配阶段，只能使用其中一块空间（From）
2 在垃圾回收GC阶段，将From中存活的对象复制到To空间
3 将两块空间的From和To名字互换

二 优点
1 吞吐量高
复制算法只需要便利一次存货对象复制到To空间即可，比标记-整理算法少了一次遍历的过程，因而性能较好，但是不如标记-清除算法，因为标记清除算法不需要对象的移动

2 不会发生碎片化
复制算法在复制之后就会将对象按照顺序放入To空间，所以对象以外的区域都是可用空间，不存在碎片化内存空间

三 缺点
内存使用效率低
每次只能让一般的内存空间来为创建对象使用

###### 标记整理算法

也叫标记压缩算法，是对标记清理算法中容易产生碎片问题的一种解决方案

一 过程
1 标记阶段，将所有存活的对象进行标记。 java中使用可达性分析算法，从GC Root开始通过引用链遍历出所有存活对象

2 整理阶段，将存活对象移动到堆的一端。清理掉存活对象的内存空间

二 优点
1 内存使用率高
整个堆内存都可以使用，不会像复制算法只能使用半个堆内存

2 不会发生碎片化
在整理阶段可以将对象往内存的一侧进行移动，剩下的空间都是可以分配对象的有效空间

三 缺点
整理算法有很多种， 比如 Lisp2 整理算法，需要对整个堆中的对象搜索三次，整体性能不佳。可以通过Two-finger , ImmixGC等高效的整理算法优化此阶段性能

Minor GC 回收新生代
如果Minor GC 后对象的年龄达到阈值（最大15，默认值和垃圾回收器有关）,对象会被晋升为老年代
当老年代中空间不足，无法放入新的对象是，先尝试minor GC， 如果还是不足， 就会触发Full GC， Full GC 会对整个堆进行垃圾回收，如果Full GC依然无法回收掉老年代的对象，那么当对象继续放入老年代时，就会抛出Out Of Memory异常

<font color="#ff0000">问题 为什么GC算法要把堆分为年轻代和老年代</font>
 分析：
 1 系统中大部分对象，都是创建出来之后很快就不再使用了，就可以被回收。比如用户获取订单数据，订单数据返回给用户之后就可以释放了
 2 老年代中会存放长期存活的对象，比如Spring中大部分bean对象，在程序启动之后就不会被回收了
 3 在虚拟机的默认设置中，新生代大小要远小于老年代大小


答：
1可以通过调整年轻代和老年代的比例来适应不同类型的应用程序，提高内存利用率和性能
2 新生代和老年代可以用不同的垃圾回收算法：新生代一般用复制算法，老年代可以选择 标记清除 或者 标记整理法
3 分代的设计中只允许回收新生代，如果能满足对象分配的要求就不要对整个堆进行回收，STW时间就会减少
[[垃圾回收器组合]]

组合一 
年轻代Serial垃圾回收器
Serial是一种单线程串行回收年轻代的垃圾回收器
优点
单CPU处理器下吞吐量非常出色
缺点
多CPU下吞吐量不如其他垃圾回收器，堆如果偏大会让用户线程处于长时间等待

老年代SerialOld垃圾回收器
采用单线程串行回收
-XX:+UserSerialGC 新生代，老年代都使用串行回收器

组合二
年轻代 ParNew垃圾回收器
使用多线程进行垃圾回收
-XX:UseParNewGC 新生代使用ParNew回收器，老年代使用串行回收器

老年代 -CMS（Concurrent Mark Sweep）垃圾回收器
CMS垃圾回收器关注的是系统的暂停时间，允许用户线程和垃圾回收器线程在某些步骤中同时执行，减少了用户线程的等待时间
参数： -XX:+UseConcMarkSweepGC
优点：
由于垃圾回收出现的停顿时间短，用户体验好
缺点：
1 内存碎片问题
2 退化问题
3 浮动垃圾问题
适用场景：
大型的互联网系统中用户请求数据量答，频率高的场景，比如订单接口，商品接口等

CMS执行步骤
1 初始标记，用极短的时间标记出GC Roots能直接关联到的对象，存在STW
2 并发标记，标记所有的对象（哪些对象需要回收，哪些对象不需要回收），用户线程不需要暂停
3 重新标记，由于并发标记阶段有些对象会发生了变化，存在错标，漏标等情况，需要重新标记。存在STW
4 并发清理，清理死亡的对象，用户线程不需要暂停

CMS缺点：
1 使用了标记-清除法，在垃圾收集结束之后会出现大量的内存碎片，CMS会在Full GC时进行碎片整理。会导致用户线程暂停，可以使用-XX:CMSFullGCsBeforeCompaction = N 参数（默认0） 调整N次 Full GC之后再整理
2 无法处理在并发清理过程中产生的 “浮动垃圾” ，比如在清理时，用户线程又创建了对象。 不能做到完全的垃圾回收。
3 如果老年代内存不足，无法分配对象，CMS就会退化成Serial Old单线程回收老年代

组合三
年轻代 PS垃圾回收器
PS是JSK8默认的年轻代垃圾回收器，多线程并行回收，关注的是系统的吞吐量。具备自动调整堆内存大小的特点
涉及算法：复制算法
优点：吞吐量高，而且手动可控。为了提高吞吐量，虚拟机会动态调整堆的参数
缺点：不能保证单次的停顿时间

老年代 PO垃圾回收器
参数：-XX:UserParallelGC 可以使用 PS + PO 这种组合
优点：并发收集，在多核CPU下效率高
缺点：暂停时间长

###### G1垃圾回收器
PS关注吞吐量，允许用户设置最大暂停时间，但是会减少年轻代可用空间大小
CMS关注暂停时间，但是吞吐量方面会下降
G1设计目标就是将上述两种垃圾回收器有点融合
1 支持巨大的堆空间回收，并有较高吞吐量
2 支持多CPU并行垃圾回收
3 允许用户设置最大暂停时间

G1垃圾回收器-内存结构
整个堆会被划分成多个大小相等的区域，称之为Region，区域不要求是连续的。分为Eden，Survivor，Old区。Region的大小通过 堆空间大小 / 2048得到 ，也可以通过参数 -XX:G1HeapRegionSize=32m指定，Region size必须是2的指数幂， 取值范围从1M到32M

G1垃圾回收有两种方式
一 年轻代回收
回收Eden区和Survivor区中不用的对象。会导致STW，G1中可以通过参数 -XX:MaxGCPauseMillis=n (默认200) 设置每次垃圾回收时的最大暂停时间毫秒数，G1垃圾回收器会尽可能地保证暂停时间

执行流程
1 新创建对象会存放在Eden区， 当G1判断年轻代区（即 Eden + Survivor）已经超过堆内存的60%，无法分配对象需要回收时，会执行Young GC
2 标记出Eden和Survivor区域中存活的对象
3 根据配置的最大暂停时间选择某些区域将存活对象复制到一个新的Survivor中，并且年龄 + 1 ，然后清空这些区域。
4 后续Young GC时与之前相同，只不过Survivor区域中存活对象会被搬运到另一个Survivor
5 当某个存活对象的年龄达到阈值（默认15），将被放入老年代
6 部分对象如果大小超过Region的一般，会直接放入老年代，这类老年代被称为Humongous区。比如堆内存是4G，每个Region就是2M，只要一个大对象超过了1M就会被放入Humongous区，如果对象过大会横跨多个Region
7 多次回收之后，会出现很多Old老年代区，此时总堆占有率达到阈值时(-XX:InitiatingHeapOccupancyPercent默认为45%) 会触发混合回收MixedGC。回收所有年轻代和部分老年代的对象以及大对象区。采用复制算法来完成

二 混合回收
1 初始标记 标记为GC Roots引用的对象为存活
2 并发标记 将第一步中标记的对象引用的对象，并且标记为存活
3 最终标记 由于在并发标记中，标记线程和用户线程并发执行，所以可能会有些漏标，错标的情况，因此这里会标记一些引用改变漏标的对象，不管新创建，不再关联的对象
4 并发清理 将存活的对象复制到别的Region中，不会产生内存碎片（使用复制算法）

G1对老年代的清理会选择存活度最低的区域来进行回收，这样可以保证回收效率最高
