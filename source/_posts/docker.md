docker是一个开源的应用容器引擎，让开发者可以打包他们的应用以及依赖到一个可移植的容器中，然后发布到任何流行的Linux机器上

什么是容器
容器是一种轻量级，可移植，自包含的软件打包技术，使应用程序可以在几乎任何地方以相同的方式运行

容器同样是一种虚拟化技术，但和虚拟机的虚拟化不一样
每个虚拟机都有自己的内核，但是容器是没有内核这一概念的，容器用的是主机内核，虚拟机用的是各自的内核

**容器的本质是进程**，同一宿主机上的容器实际是承载与该宿主机内核之上的进程

容器之间的隔离是文件系统与进程的隔离，**内核并不隔离**



| 特性         | 虚拟机       | 容器             |
| ------------ | ------------ | ---------------- |
| 启动         | 分钟级       | 秒级             |
| 硬盘使用     | 一般为GB     | 一般为MB         |
| 性能         | 弱于原主机   | 接近原主机       |
| 系统支持类型 | 多样化       | 与原主机内核相同 |
| 单机支持量   | 几十个虚拟机 | 上千个容器       |
| 安全性能     | 极高         | 较高             |



docker的优势

一致的环境：一致的调试，测试和生产环境

应用隔离：应用进程之间相互隔离，互相不干扰

高效的资源利用率：平均约2%的资源损耗率，远低于虚拟机，启动速度极快



docker的劣势

缺乏多样性的内核支持：同一宿主机上的容器共享同一宿主机内核；宿主机不能随意使用定制内核

安全性略低于虚拟机



应用场景：

生产/运维 ： 生产多应用隔离部署

测试和开发可以用一个环境，方便发现问题

开发可以快速搭建调试环境

测试可以有一致可复现的环境



### docker核心概念

#### 仓库，镜像，容器是什么

##### 镜像 Image

类似于虚拟机的虚拟磁盘，但是镜像是只读的

比如 官方镜像ubuntu:16.04 就包含了一套完整的Ubuntu16.04最小系统的root文件系统

镜像通常存储与注册服务器Registry的仓库中，使用docker pull命令可以从仓库中拉取镜像， 使用docker push可以将镜像推送到仓库保存

通过dockerFile制作



##### 镜像的分层存储 Layer

1. 镜像实际上是由多层"文件系统"组成的，每层“文件系统”称之为一层layer
2. 镜像是逐层layer构建起来的，前一层是后一层的构建基础。每一层构建完成就不再变化，即变为制度曾
3. 如果构建时要删除前一层中的某个文件，实际上不是到前一层的layer上去删除文件，而是在当前构建层中标记该文件“已经删除”；
4. 同理，如果构建时要修改前一层中的某个文件，实际是在当前构建曾中记录该文件修改的数据
5. 分层存储的特征使得镜像的复用，定制变得更为容易



##### 容器 Container

1. 镜像和容器的关系，就像是 面向对象编程（OOP）中的 “类” 和 “实例” 的关系一样，是镜像运行的实例
2. 容器的实质是进程
3. 容器可以被创建，启动，停止，删除，暂停等
4. 容器启动时会基于镜像从创建一层可写的layer，用于记录容器运行时的文件系统变化
5. 容器 commit之后即变为新的镜像，可写layer也同时变成新镜像的read-only layer, 通常不推荐以这种方式生成新的镜像



##### 仓库与注册服务器（Repository & Registry）

一个注册服务器(Registry) 可以包含多个仓库(Repository); 一个仓库可以包含多个镜像

一个注册服务器可以包含多个仓库，一个仓库可以包含多个镜像

仓库是集中存放镜像的地方

同一个仓库中的不同镜像用不同的标签(Tag)来区别

同一个镜像可以有多个标签

也就是说，一个镜像需要有<Reigstry><Repository><Tag>三部分才能确定



SVN服务器就可以类比于注册服务器

SVN仓库就可以类比于仓库

SVN的commit之后的版本号就类似于tag



一个完整的镜像名称格式为：[Registry]/[Repository]:[Tag]

[Registry]为地址格式，可以是域名或者IP。若镜像名中省区Registry，则表示为官方Registry地址(docker.io)

[Repository]通常为两段式名称，即<用户或项目名> / <软件名>。 如果官方镜像省去<用户或者项目名>,则表示为<用户或项目名>为library

[Tag]为标签名称，如果省区Tag，则表示Tag为"latest"
