##  共享模型之管理线程

一段代码块内如果存在对共享资源的多线程读写操作，称这段代码块为临界区

### 1 synchronized

synchronized 是阻塞式方案，俗称 对象锁，它采用互斥的方式让同一时刻之多只有一个线程能持有对象锁，其他线程在想获取这个对象锁时就会阻塞住。这样就能保证拥有锁的线程可以安全的执行临界区的代码，不用担心线程上下文的切换

``` java

import lombok.extern.slf4j.Slf4j;  
  
@Slf4j(topic = "test17")  
public class Test17 {  
  
  
public static void main(String[] args) throws InterruptedException {  
Room room = new Room();  
Thread t1 = new Thread(() -> {  
for (int i = 0; i < 1000; i++) {  
room.increment();  
}  
});  
Thread t2 = new Thread(room::decrement);  
  
t1.start();  
t2.start();  
t1.join();  
t2.join();  
  
log.debug("{}", room.getCounter());  
}  
}  
  
class Room {  
private int counter = 0;  
  
public void increment() {  
synchronized (this) {  
counter++;  
}  
}  
  
public void decrement() {  
synchronized (this) {  
counter--;  
}  
}  
  
public int getCounter() {  
synchronized (this) {  
return counter;  
}  
}  
}

```

可以加载方法上

``` java

class Test {  
public synchronized void test() {  
}  
}

// 等价于 

class Test {

}


```

### 2 线程安全分析

成员变量和静态变量是否安全？

如果没有被共享 则线程安全
如果被共享，分两种情况
1 如果只有读操作 则安全
2 有读有写的话，则这段代码时临界区，则不安全

局部变量是不是线程安全？

**是的**

但局部变量引用的对象未必安全
- 如果该对象没有逃离方法的作用范围，则是线程安全的
- 如果该对象逃离方法的作用范围，则是不是线程安全的

#### 暴露引用

如果有子类继承了父类的 public方法 并重写了，会出现 暴露引用的问题

#### 常见线程安全类
String Integer StringBuffer Random Vector Hashtable java.util.concurrent包下的类
他们每个方法都是原子的，但是他们多个方法的组合并不是原子的！

Integer等都是不可变类，因为期内不得状态不可以改变，因此它们的方法都是线程安全的，比如String类里的 substring replace 等方法，但是他们是new String 新建个对象，原来的值不变

外星方法：比如一个类有一个抽象方法，但这个抽象方法可以被继承的类实现。 因此这种可能是不安全的

开闭原则 ：即开放封闭原则，是指软件实体(类，模块，方法等) 应当是可扩展的，不是可修改的。在不修改已有代码的前提下，扩展新的功能（比如String类，就是定义为final，防止自己的方法被继承的类修改）
在Java中，可以通过以下方式来遵守开闭原则：
1. 抽象化：为系统的可变部分制定好接口，而不去实现它们。
2. 封装变化：将可能变化的部分封装起来。
3. 多用组合少用继承：可以使用组合来替代类的继承，以获得更大的灵活性。
4. 使用依赖注入：依赖注入可以使得在运行时动态地将依赖关系注入到对象中。

### 4 wait /notify
![[wait_notify-图1.png]]

![[wait_notify-图2.png]]

![[wait_notify-图3.png]]


Api介绍

object.wait() 让进入object 监视器的线程到waitSet等待
obj.notify() 在 obj 上 正在waitSet等待的线程中挑一个唤醒
obj.notifyAll() 在 obj 上 正在waitSet等待的线程中全部唤醒

#### 一 wait notify正确使用

sleep(long n) 和 wait(long n) 的区别
1. sleep是Thread的方法， wait是 Object的方法
2. sleep不需要和synchronized一起用， 但wait需要
3. sleep在睡眠同时 不会释放锁，但wait会
4. 他们的线程状态都是一样 TIMED_WAITING

用 锁对象的话 在前面加上final，保证引用不会被修改

```
synchronized(lock) {
	while(false){
		lock.wait();
	}
}

synchronized(lock) {
	lock.notifyAll();
}
```

### 5 park unpark

unpark 既可以在某个线程之前调用，也可以在某个线程之后调用

1 wait notify notifyAll 必须配合 Object Monitor 一起使用，但是unpark不需要 因为是 LockSupport的方法

2 park 和 unpark 是以线程为单位来 阻塞 和 唤醒 线程，而 notify 只能随机唤醒一个等待线程，notifyAll 是唤醒所有等待线程

3 park & unpark 可以先 unpark， 而 wait &  notify 不能先 notify

### ReentrantLock

相对于 synchronized 来说  具备一下特点
- 可中断
- 可以设置超时时间
- 可以设置为公平锁（防止饥饿）
- 支持多个条件变量（多个waitset，即不满足条件一的去一个waitset 不满足条件二的去另一个waitset）

#### 一 可重入
可重入是指同一个线程如果首次获得了这把锁，那么因为他是这把锁的拥有者，因此有权利再次获取这把锁。如果是不可重入锁的话，第二次获取锁的时候，自己就也会被挡住

和synchronized一样，都支持可重入区别在于：
sychronized是会自动释放，但是reentrantLock需要手动释放

``` java

import lombok.extern.slf4j.Slf4j;  
  
import java.util.concurrent.locks.ReentrantLock;  
  
@Slf4j  
public class Test22 {  
  
private static ReentrantLock lock = new ReentrantLock();  
public static void main(String[] args) {  
lock.lock();  
try {  
log.info("1");  
m1();  
} finally {  
lock.unlock();  
}  
}  
  
public static void m1() {  
lock.lock();  
try {  
log.info("emter m1");  
m2();  
} finally {  
lock.unlock();  
}  
}  
  
public static void m2() {  
lock.lock();  
try {  
log.info("emter m2");  
  
} finally {  
lock.unlock();  
}  
}  
}
```

####  二 可打断 
该机制是防止出现死锁的一种方式
``` java
import lombok.extern.slf4j.Slf4j;  
  
import java.util.concurrent.locks.ReentrantLock;  
  
@Slf4j  
public class Test22 {  
  
private static ReentrantLock lock = new ReentrantLock();  
public static void main(String[] args) throws InterruptedException {  
Thread t1 = new Thread(() -> {  
try {  
log.debug("try to get lock");  
lock.lockInterruptibly();  
} catch (InterruptedException e) {  
throw new RuntimeException(e);  
}  
try {  
log.debug("get lock");  
} finally {  
lock.unlock();  
}  
}, "t1");  
  
lock.lock();  
t1.start();  
Thread.sleep(1000);  
log.debug("interrupt t1");  
t1.interrupt();  
}  
  
}
```

#### 四 条件变量
ReentrantLock的条件变量 比 sychronized强大之处在于，它是支持多个条件变量的，比如
1 synchronized 是那些不满足条件的线程都在一间休息室等消息
2 而ReentrantLock支持多个休息室，唤醒也是按休息室来唤醒

``` java
import lombok.extern.slf4j.Slf4j;  
  
import java.util.concurrent.TimeUnit;  
import java.util.concurrent.locks.Condition;  
import java.util.concurrent.locks.ReentrantLock;  
  
import static java.lang.Thread.sleep;  
  
@Slf4j  
public class Test22 {  
  
private static ReentrantLock lock = new ReentrantLock();  
public static void main(String[] args) throws InterruptedException {  
  
// 创建新的条件变量  
Condition condition1 = lock.newCondition();  
Condition condition2 = lock.newCondition();  
  
lock.lock();  
// 等待condition1  
condition1.await();  
  
condition1.signal();// 唤醒condition1的第一个线程  
condition1.signalAll();// 唤醒condition1的所有线程  
  
  
}  
  
}
```


使用流程
1 await前需要获得锁
2 await执行后 会释放锁，进入conditionObject等待
3 await的线程被唤醒（interrupt， signal， 或者 await设置超时时间），去重新竞争lock锁
4 竞争lock锁成功后，从await后继续执行
